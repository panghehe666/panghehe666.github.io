> 前面写过一篇 [介绍 Grok](/2026/10/07/introduce-grok/)，聊的是海外那一挂。这篇补上国内的：阿里在 2026 年 3 月把 AI 的总称和核心品牌统一成了「千问」，App、模型、开发者平台全都叫这个名字。用了一段时间，最大的感受是它跟别的助手不太一样——**别人在努力回答得更好，它在努力替你把事办完。**

## 1. 千问是什么

一句话：**千问是阿里巴巴推出的 AI 助手，底层跑的是 Qwen 系列大模型。**

它其实有两层含义，容易混：

- **千问大模型（Qwen）**：阿里的开源模型家族，2023 年 8 月首次开源，一路迭代到 Qwen3.8 系列。
- **千问 App / 千问 AI 平台**：面向普通用户的客户端，和面向开发者的 API 平台。

改名这条线捋一下就清楚了：2023 年 10 月上线时叫「通义千问 App」，2024 年 5 月简化成「通义 App」，2025 年 11 月升级为「千问 App」，公测首周下载量破了千万；到 2026 年 3 月 2 日，阿里干脆把 B 端 C 端品牌全统一成「千问」。所以现在不管你在应用商店搜到的、还是开发者文档里看到的，都是同一个名字。

安卓包名还是老的 `com.aliyun.tongyi`，能看出它的出身。

## 2. 最不一样的一点：它能动手办事

大部分 AI 助手的天花板是「给你建议」——它告诉你去哪吃、买什么、怎么办，然后你自己打开五个 App 一个个操作。

千问在 2026 年 1 月 15 日的发布会上把这条路走通了：**全面接入淘宝、支付宝、淘宝闪购、飞猪、高德等阿里生态业务，一次性上线超 400 项 AI 办事功能。**

具体能干什么：

| 场景 | 你说一句 | 它做的事 |
|---|---|---|
| 点外卖 | 「帮我点两杯拿铁」 | 调淘宝闪购定位、推商家、生成订单，用内置「支付宝 AI 付」直接付款 |
| 买东西 | 「给爸妈买个扫地机器人，预算 2000-4000，家里有猫」 | 推理出防缠绕、高温杀菌这些隐含需求，基于淘宝真实交易数据推荐 |
| 订行程 | 「下周去成都玩三天」 | 生成一个网页版攻略，路线直接画在高德地图上，门票住宿一键跳飞猪 |
| 办政务 | 「杭州户口怎么办护照」 | 政策解读 + 材料清单，直达办理入口（签证、户口、公积金等 50 项民生服务） |
| 订餐厅 | 「帮我订个位置」 | 真的会打电话过去 |

发布会现场那个演示挺有名：一句「帮我点 40 杯霸王茶姬的伯牙绝弦」，千问直接下单支付，然后骑手把奶茶送到了会场。

关键是**支付宝的「AI 付」**——这是给智能体设计的原生支付能力，不用跳转别的 App，官方说操作步骤能减少 60% 以上。安全上是「自主开通 + 本人支付 + 被盗即赔」三重保障，付款时要面容、指纹或密码核身。

说白了，AI Agent 的公式是「最强大脑 + 最强肢体」。OpenAI 有脑子缺支付物流，亚马逊有物流模型在追赶，谷歌微软的生态又基本停在数字世界里。阿里是少数两头都攥着的，这是千问能先跑通办事闭环的根本原因。

## 3. 干活和学习的能力

2026 年 8 月 7 日那次更新加了不少硬货，而且**所有用户免费**：

- **思考研究**：原「深度思考」的升级版，推理和信息整合更强，面向复杂专业问题给研究级回答。
- **工作助理 / 办公助理**：能自主拆解目标、调用工具、交付成果，直接产出网页、应用、PPT、Word、Excel、图片这类成品文件，打开即用。支持手机和 PC 跨端协同，任务在后台跑完会推通知，不用盯着。有实测让它写一份 AI 发展历程报告，交出来 36 页、2.6 万字。
- **定时任务**：周期性和一次性两种，到点自动触发执行并交付结果。
- **智能体广场**：官方品牌智能体入驻，对话里 `@` 一下就能唤起。
- **语音通话**：7×24 小时在线，陪玩、睡前故事、带娃讲题、语音打车都行。

文档这块也不弱：一次能传 10 个文档 / 图片，500 页长文照样处理；实时记录支持离线或在线语音转文字，自动出会议纪要和待办。

学习场景有「千问小讲堂」，AI 老师可视化板书讲解、实时语音答疑；拍题答疑覆盖全学段全学科；作业和口算批改会生成错题本；背后还有个 5 亿量级的资料库。

生图生视频用的是 Wan 3.0 视频生成模型和 Qwen-Image，Wan 3.0 支持单段 30 秒视频生成。

## 4. 底子：Qwen 的开源生态

千问 App 好不好用，最终取决于 Qwen 强不强。这块的数据挺夸张：

- 累计开源 **460 多个**模型，全球下载量突破 **30 亿次**，衍生模型超 **30 万个**（截至 2026 年 8 月）。
- Hugging Face《开源模型现状》报告（2026 年 8 月 14 日）：同期谷歌约 4.18 亿次、Meta 约 2.27 亿次下载，Qwen 光在 HF 上就有 20.45 亿次。报告原话是 Qwen「已成为开发者决定微调和部署哪些模型时默认工作流的一部分」。
- 2026 年 9 月 16 日，Qwen3.8-27B 超过 FLUX.1、DeepSeek-R1、Kimi-K3、Llama-3，成为 HF 历史上点赞最多的开源模型，海外社区叫它「本地 Opus4.6」。
- 2026 年 8 月 13 日，阿里首次开源 Max 级别的旗舰模型 Qwen3.8-2.4T-A95B（2.4 万亿总参数，每 token 激活 950 亿）。Unsloth 用动态 1-bit 分层量化把 4.9TB 压到 397GB，410GB 内存 + 显存就能本地跑。
- 2026 年 2 月成为国际奥委会官方大模型，用在米兰冬奥会赛事服务上；9 月比亚迪宣布千问接入座舱体系。

## 5. 怎么用

**普通用户**，三个入口：

1. **手机 App**：应用商店搜「千问」，iOS 版在 App Store 显示开发者为上海智信普惠科技有限公司，安装包 500 多 MB。淘宝 / 支付宝 / 手机号一键登录。⚠️ 一定要登录，文档分析、PPT 生成这些核心功能没登录用不了。
2. **网页版**：功能和 App 基本一致，办公场景更顺手。
3. **桌面端 / PC 客户端**：跨端协同，任务后台跑。

**开发者**，走千问 AI 平台或阿里云百炼：账号就是阿里云账号，支持手机号、密码、支付宝扫码、千问扫码四种登录方式。API Key 在业务空间里创建，建议塞进环境变量（如 `DASHSCOPE_API_KEY`）别硬编码。接入方式有 OpenAI 兼容接口和 DashScope SDK 两种——存量项目迁移用前者方便，但百万长上下文、多模态图文、批量文档上传这些独有能力只有原生接口支持。

计费上，千问 App 的「工作助理」目前只支持 Token Plan（个人版 / 团队版），不支持按量计费，两种方案的 Key 不通用，配错了会校验失败。

## 6. 横向对比：千问 vs DeepSeek vs Grok

前面讲的都是千问自己有什么，但真要选型，关心的是「跟别的比怎么样」。我手上三个都在用——千问 App、DeepSeek（安卓端跑 Harness，见 [玩转 DeepSeek Harness 安卓端](/2026/10/17/deepseek-harness-android/)）、Grok（见 [介绍 Grok](/2026/10/07/introduce-grok/)）。下面按几个维度拆开说。

### 6.1 背景与定位

| 维度 | 千问 | DeepSeek | Grok |
|---|---|---|---|
| 背后公司 | 阿里巴巴 | 深度求索（杭州） | xAI（Elon Musk） |
| 定位 | AI 助手 + 开源模型生态 | 深度推理 + 开源模型 | AI 助手 + 实时信息 |
| 核心优势 | 阿里生态整合、AI 办事能力 | 深度推理、代码能力、性价比 | X(Twitter) 实时信息、GitHub 集成 |

### 6.2 应用端体验：我最看重的一点

| 维度 | 千问 | DeepSeek | Grok |
|---|---|---|---|
| **应用端能否直接办事** | 原生打通淘宝/支付宝/闪购/飞猪/高德，一句话下单付款 | App 只能聊天，要动手得自己接 API 到第三方 harness | Build 模式能跑项目、改仓库，但有额度限制 |
| **改博客这类活** | 千问 Go! 里直接说需求，它自己克隆仓库、写文件、提交、轮询到上线 | 得靠 Harness 类客户端 + 自己的 API Key，token 自己掏 | Build 模式能做，重度用会撞额度墙 |
| **成本** | App 端核心功能免费 | API 按 token 计费，跑 Agent 很烧 | 免费额度有限，超了要订阅 |
| **工具链** | 大脑 + 手脚 + 工具链一体，装在一个 App 里 | 只给大脑，手脚自己配 | 大脑 + GitHub/X 连接器 |
| **生态绑定** | 强绑阿里系（这也是它的短板） | 无生态，纯模型 | 绑 X 和 GitHub |
| **开源 / 本地部署** | 460+ 模型开源，27B 量化后笔记本能跑 | 开源，本地部署友好 | 不开源 |
| **实时信息** | 联网搜索 | 需自行接搜索 | 原生实时刷 X，这块无可替代 |

#### 为什么我说「最牛的地方在应用端」

先摆个我自己的真实数字。DeepSeek Harness 后台统计，**最近 30 天**：

- Tokens 用量：**138,766,482**（138.8M）
- 会话 102 次，请求 975 次
- 平均缓存命中率 **98.2%**（135.3M 命中）
- 活跃天数只有 **4** 天
- 最常用模型：`deepseek-flash`

注意这个组合：**缓存命中都干到 98.2% 了，token 还是烧掉 1.38 亿，而且只用了 4 天。** 这不是我省不下来，是 Agent 类任务的结构性开销——每一轮都要把文件内容、命令输出、上一轮的中间结果重新塞进上下文，轮数一多就是指数级往上走。省 token 那套技巧（见我上一篇）能压，但压不到零。

同样一件事：「帮我把这篇文章发到我博客上」。三条路线的实际差别是：

**DeepSeek 路线** —— 模型本身很强，但它自己不知道你的仓库在哪、没有 git、没有网络出口。你得先搭一个 Harness 客户端、配 API Key、写系统提示、把 GitHub token 塞进去。搭完确实能用，我那个博客的 AI 问答模块就是这么跑的。但**每一步都在烧你自己的 token**，而且环境要自己维护。

**Grok 路线** —— Build 模式是真的能连 GitHub 直接改仓库、提 commit，我之前那篇《介绍 Grok》就是它自己发上去的。体验很爽，**问题在额度限制**：重度使用会撞墙，撞到就得等或者上订阅。

**千问路线** —— 在千问 Go! 里说一句「读一下我的博客，写篇介绍千问的文章发上去」，它自己去抓站点结构、查资料、照着你仓库的 front matter 模板写、调 Contents API 提交、然后轮询目标 URL 到 200 才回你「已发布上线」。**你现在读到的这篇文章，就是这么发出来的**——从我提出需求到线上可访问，中间我没打开过一次电脑。

差别的本质：**前两者是「给你一个很强的大脑，手脚自己配」；千问是「大脑 + 手脚 + 工具链一起给你，而且全装在一个 App 里」。**

对重度用户来说，省下来的不只是 API 账单，还有搭环境、调 prompt、维护 harness 的那些时间。这些时间成本通常比 token 贵得多。

#### 但也别一刀切

这是我这个场景（写博客 + 跑小项目 + 手机端为主）下的结论，不代表普适：

- 只需要一个纯聊天 / 写代码的模型，**DeepSeek 性价比很高**，flash 系列尤其便宜，本地部署也友好。
- 重度依赖 X（Twitter）上的实时信息，**Grok 目前没有替代品**。
- 日常用的不是淘宝 / 支付宝 / 飞猪 / 高德那一套，千问的办事能力**大部分落不了地**，那就只剩一个还不错的聊天助手。

### 6.3 三家各自的强项

**千问** 最强的是「办事」能力——接入淘宝、支付宝、飞猪、高德等阿里生态，能直接下单、订票、付款。办公助理能生成 PPT/Word/Excel 成品文件，思考研究面向复杂专业问题给研究级回答，文档处理一次传 10 个文件、500 页长文照样处理。生图生视频用的是 Wan 3.0 模型。简单说，千问想做的是「从意图到执行」的全链路。

**DeepSeek** 最强的是深度推理和代码能力。R1 模型通过强化学习在数学、代码、自然语言推理等任务上对标 OpenAI o1，V4.1-Flash 系列持续迭代，在代码生成、Agent 任务上表现亮眼。最新还开放了自研搜索 API 和 Fetch API（网页抓取），百万级上下文窗口（1M tokens），以及「Wish-Driven Programming」端到端项目生成——你描述需求，它自己规划、写代码、检查、修复，一直跑到可运行状态。

**Grok** 最强的是实时信息获取和开发者工具链。原生接入 X(Twitter)，能实时搜索话题、看帖子线程；GitHub 连接器让你直接在对话里读仓库、提交 PR、开 Issue；Build 模式在沙箱里跑代码、改项目；还有跨会话记忆功能，越用越顺手。基础使用免费，对独立开发者和折腾博客的人来说门槛很低。

### 6.4 开源生态

- **千问**：最激进的开源派。累计开源 460+ 模型，Hugging Face 下载量 20.45 亿次（同期谷歌约 4.18 亿、Meta 约 2.27 亿），Qwen3.8-27B 是 HF 历史上点赞最多的开源模型。Max 级旗舰 Qwen3.8-2.4T 也开源了，量化后笔记本能跑。
- **DeepSeek**：同样拥抱开源。R1 用 MIT 协议开源，V3/V4 系列全开源，还蒸馏了 1.5B~32B 小模型覆盖移动端部署，社区生态很活跃。
- **Grok**：闭源。模型权重不公开，通过 API 和 App 使用，生态主要围绕 X 平台和 GitHub 连接器展开。

### 6.5 适合谁

- 想**让 AI 帮你办事**（点外卖、订票、做 PPT、处理文档）→ 千问
- 想**让 AI 帮你写代码、做研究、跑复杂推理、分析长文档**→ DeepSeek
- 想**让 AI 帮你刷推特、改 GitHub 仓库、写博客、跑小项目**→ Grok

三家其实不是替代关系，更像是「三把不同的锤子」——你手里钉子是什么材质，选哪把就对了。我目前三个都在用，各自分管不同的场景。

## 7. 一点使用感受

跟我之前用的几个助手比，千问最明显的差别是**它把「跳转」这个动作给消掉了**。

以前用 AI 做旅行攻略，得到的是一篇文字，然后我还得自己去查地图、比机票、找酒店。千问直接给你一个网页，路线画在高德上，每个景点带图文介绍，点一下就跳导航或打车，门票住宿一键跳飞猪。信息量差不多，但我少干了七八步活。

要说缺点也有：办事能力强绑定阿里生态，如果你日常用的是美团、携程那一套，很多能力就落不了地；另外这类「AI 直接下单支付」的功能，第一次用还是建议盯着确认一遍，别一上来就让它替你做决策。

适合谁：

- 想找个能真办事、而不只是聊天的 AI
- 本来就在用淘宝 / 支付宝 / 飞猪 / 高德
- 有文档处理、报告撰写、PPT 这类办公需求
- 开发者想在本地跑开源模型，Qwen3.8-27B 那个尺寸量化后笔记本就能塞进去

## 结语

大模型卷了两年，参数刷到天上，落地还是「帮我写首藏头诗」。千问这次的价值不在于又发了个更强的模型，而在于它把「从意图到执行」这最后一公里给补上了——**AI 竞赛的焦点，正在从跑分转向谁能真的替你干活。**

这条路刚开始，能力还在探索期。但方向我觉得是对的。
